AMNAISYS — Namecheap cPanel / Microsoft Graph + Google Sheets form deployment notes (v40)

1. Upload the CONTENTS of this folder to the document root (normally public_html).
2. Keep .htaccess and submit-form.php in the document root.
3. Ensure inquiries@amnaisys.com exists and is monitored in Microsoft 365 / Outlook.
4. All four forms (EN/AR Contact and EN/AR Consultation) post to the same submit-form.php.

5. IMPORTANT — PRESERVE THE ALREADY-WORKING LIVE CONFIGURATION
   The supplied submit-form.php is built from the current working Graph + Google Sheets handler.
   In the review copy the following values are intentionally represented as SECRET placeholders:
      M365_TENANT_ID
      M365_CLIENT_ID
      M365_CLIENT_SECRET
      GOOGLE_SHEET_WEBHOOK_URL

   Before replacing the live handler, copy the REAL values from the currently working production
   submit-form.php into those same four constants. Do not invent, regenerate, rename, or otherwise
   change the working Microsoft Entra / Microsoft 365 or Google Apps Script configuration.

6. MICROSOFT 365 DELIVERY — EXISTING WORKING GRAPH TRANSPORT IS PRESERVED
   submit-form.php uses Microsoft Graph over HTTPS/443 with OAuth 2.0 client credentials.
   Transport flow remains:
      - acquire the application token from Microsoft identity platform;
      - call /users/inquiries@amnaisys.com/sendMail;
      - deliver to inquiries@amnaisys.com;
      - save a copy in Sent Items;
      - use the visitor's validated email + submitted name in Reply-To.

   Do not replace this working Graph transport with PHP mail() or the retired SMTP implementation.

7. GOOGLE SHEETS — EXISTING WORKING WEBHOOK IS PRESERVED
   After Microsoft Graph accepts the email, the same validated lead is posted to the existing
   Google Apps Script webhook. Google Sheets remains NON-BLOCKING: a Sheet/webhook failure is
   written to the PHP error log but does not turn an already-delivered inquiry into a visitor error.

8. SERVER-SIDE HARDENING ADDED AROUND THE EXISTING WORKING DELIVERY
      - scalar-only POST reading;
      - Unicode-safe character lengths;
      - Name: 2–100 characters; Unicode letters/marks, spaces, apostrophes and hyphens only; no digits or other symbols;
      - Company: 2–150 characters; Unicode letters/numbers/marks and spaces only;
      - Email: valid syntax, maximum 254 characters, common business-email characters only, complete domain form;
      - Phone: Western/Arabic-Indic digits, spaces, optional leading +; 7–15 actual digits;
      - maximum 25 typed phone characters;
      - Project Scope / Requirement: 20–1000 characters;
      - Contact Service allowlist;
      - Consultation Service allowlist;
      - Consultation Industry / Company Size / Project Stage / Budget / Contact Method allowlists;
      - existing honeypot retained;
      - low-friction too-fast submission guard when JavaScript timing exists;
      - per-IP rate limiting: max 5 submissions / 10 minutes and 20 / 24 hours;
      - identical inquiry suppression for 30 minutes;
      - duplicate reservation released if Graph delivery fails, so a legitimate visitor can retry.

   Rate-limit/duplicate state is stored in the PHP system temporary directory using flock().
   If that storage is unavailable, these two guards fail open rather than disabling the forms;
   field validation + honeypot still remain active.

9. FRONTEND VALIDATION + VISUAL CONTRACT
   The four form pages load assets/css/forms.css after the existing stylesheets. It is the single
   authoritative visual contract for Contact + Consultation controls: field background, border,
   radius, height, placeholder tone, focus ring, textarea sizing, autofill and form-card hover.

   main.js primes localized customValidity messages and then enables a runtime noValidate flow only
   after the handlers are installed. Submit attempts explicitly report the first invalid field, so
   Contact and Consultation show deterministic localized browser prompts instead of silently jumping
   to an invalid field or falling back to generic Chrome wording. If JavaScript fails to load, the
   original HTML required/min/max/type constraints remain available as the browser fallback.

   Name/Company/Business Email are sanitized while typing/pasting to remove disallowed characters;
   the PHP handler independently repeats the same rules so direct POSTs cannot bypass them.

   The blank REQUIRED Service option is value="" + selected and is not disabled. Required validation
   still blocks it. Required and optional closed selects now use the same dark text tone; Contact
   displays "Select a service" / "اختر خدمة" without trailing ellipses. Native popup colors and
   scrollbars remain browser/OS UI.

10. PHP / HOSTING REQUIREMENTS
      - PHP 8.x recommended;
      - PHP cURL extension enabled;
      - outbound HTTPS on port 443 allowed;
      - JSON support enabled;
      - sys_get_temp_dir(), flock(), and normal temporary-file writes available;
      - ModSecurity should remain enabled in cPanel.

11. LIVE VERIFICATION AFTER DEPLOYMENT
   Submit all four paths once:
      /en/contact.html
      /ar/contact.html
      /en/consultation.html
      /ar/consultation.html

   Confirm for each:
      - correct thank-you redirect;
      - email arrives at inquiries@amnaisys.com;
      - Sent Items copy exists;
      - Reply-To contains the visitor's submitted name/email;
      - subject contains visitor name + company;
      - Arabic content renders correctly;
      - one corresponding Google Sheet row is appended.

12. VALIDATION / ABUSE SMOKE TESTS
      - blank required Service displays the custom localized service-selection message;
      - malformed email displays the custom localized valid-email message;
      - phone rejects <7 or >15 actual digits;
      - Project text rejects <20 or >1000 characters server-side;
      - tampered select values are rejected server-side;
      - honeypot submission silently redirects and sends neither email nor Sheet row;
      - deliberate reload starts the form clean;
      - an identical valid inquiry within 30 minutes does not generate duplicate mail/Sheet rows;
      - sixth valid attempt within 10 minutes from one server-observed IP receives HTTP 429.

13. If a form returns the friendly failure page, inspect the PHP error log.
   Existing Graph failures are logged as "Microsoft Graph Token Error ..." or
   "Microsoft Graph sendMail Error ...". Existing Google Sheet failures are logged as
   "Google Sheets Webhook Error ...". Technical responses are never exposed to visitors.

14. Do not rename submit-form.php unless all four form action attributes are updated as well.
