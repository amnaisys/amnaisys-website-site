AMNAISYS — Namecheap cPanel / Microsoft Graph form-delivery deployment notes

1. Upload the CONTENTS of this folder to the document root (normally public_html).
2. Keep .htaccess and submit-form.php in the document root.
3. Ensure the mailbox inquiries@amnaisys.com exists and is monitored in Microsoft 365 / Outlook.
4. The four website forms (EN/AR Contact and EN/AR Consultation) all post to submit-form.php.

5. FORM DELIVERY — VERIFIED MICROSOFT GRAPH TRANSPORT
   submit-form.php uses the Microsoft Graph API over HTTPS/443 with OAuth 2.0 client credentials.
   The manually configured Microsoft Entra / Microsoft 365 application values in submit-form.php are
   the working production transport configuration and must be preserved when updating the site.

   Transport flow:
      - acquire an application access token from the Microsoft identity platform;
      - call Microsoft Graph /users/inquiries@amnaisys.com/sendMail;
      - deliver to inquiries@amnaisys.com;
      - save a copy to Sent Items;
      - set Reply-To to the visitor's validated email address and submitted name.

   Do not replace this working Graph transport with PHP mail() or the earlier SMTP implementation.

6. OUTLOOK MESSAGE PRESENTATION
   The authenticated sender remains the Microsoft 365 AMNAISYS mailbox.
   Visitor identity is made clear through:
      Reply-To: <visitor name> <visitor email>
      Subject: [AMNAISYS] Contact Inquiry / Consultation Request — <visitor name> — <company>
      Body: submitted name, company, email, phone, service/form details and project message.
   This preserves the verified Microsoft sender identity while making the actual inquiry contact obvious.

7. SERVER-SIDE FORM HARDENING IN submit-form.php
      - required-field and length validation independent of the browser;
      - Name: 2–100 Unicode characters;
      - Company: 2–150 characters;
      - Email: valid syntax, maximum 254 characters;
      - Phone: 7–15 actual digits after formatting removal, maximum 25 typed characters;
      - Project Scope / Requirement: 20–1000 characters;
      - required Service value allowlisting;
      - Consultation optional-select allowlisting;
      - honeypot protection;
      - per-IP rate limiting: maximum 5 submissions / 10 minutes and 20 / 24 hours;
      - duplicate inquiry suppression for 30 minutes;
      - low-friction too-fast-submission signal when JavaScript timing data is available.

   Rate-limit/duplicate state uses the PHP system temporary directory. If temporary storage cannot be
   created, the guard fails open so legitimate form delivery is not disabled; core validation and the
   honeypot remain active.

8. PHP REQUIREMENTS ON THE NAMECHEAP ACCOUNT
      - PHP 8.x recommended;
      - PHP cURL extension enabled;
      - outbound HTTPS connections on port 443 allowed;
      - JSON support enabled;
      - sys_get_temp_dir(), flock(), and normal temporary-file writes available for anti-abuse state.

9. Keep ModSecurity enabled in cPanel. Form validation/rate limiting mitigates form abuse but is not a
   replacement for edge/network DDoS protection.

10. HTTPS must be enabled before production. The included HSTS rule assumes HTTPS operation.

11. LIVE FORM VERIFICATION AFTER DEPLOYMENT
   Submit all four production paths:
      /en/contact.html
      /ar/contact.html
      /en/consultation.html
      /ar/consultation.html

   For each test confirm:
      - correct EN/AR thank-you redirect;
      - message arrives at inquiries@amnaisys.com;
      - subject contains visitor name and company;
      - Reply-To contains the visitor's submitted name and email;
      - Arabic content is readable and preserved;
      - a sent copy appears in Microsoft 365 Sent Items.

12. VALIDATION / ABUSE SMOKE TESTS
      - malformed email is blocked with a localized browser message;
      - required Service shows the custom EN/AR service-selection message;
      - phone rejects fewer than 7 or more than 15 actual digits;
      - project text rejects fewer than 20 or more than 1000 characters;
      - tampered select values are rejected server-side;
      - a deliberate page reload clears form values;
      - an identical valid submission within 30 minutes does not generate a second email;
      - excessive submissions from one IP receive a rate-limit response.

13. If a form returns the friendly "Unable to send your request" page, inspect the PHP error log.
    Graph token failures are logged as "Microsoft Graph Token Error ..." and send failures as
    "Microsoft Graph sendMail Error ...". Technical responses are never shown to visitors.

14. Do not rename submit-form.php unless all four form action attributes are updated as well.
